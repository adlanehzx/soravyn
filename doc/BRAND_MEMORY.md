# Brand Memory and Verifiable Knowledge

SORAVYN's brand memory is the base of verifiable knowledge that anchors every creative brief, script and advertising campaign generated by the autonomous agents.

It eliminates hallucinations, guarantees compliance with the client's real pricing and sales promise, and applies a deterministic analysis engine that immediately flags missing or contradictory information.

---

## 1. Deterministic data model

All entities are partitioned at client level (`company_id`), protected by a unique index and access-rights checks (`assertCompanyAccess`, `assertBoard`).

### PostgreSQL tables (`@soravyn/db`)

1. **`brand_products`**: offers and products sold
   - `id` (UUID PK)
   - `company_id` (UUID FK -> `companies.id` ON DELETE CASCADE)
   - `name` (varchar 200, required)
   - `category` (varchar 100)
   - `description` (text)
   - `pricing` (varchar 100, required to validate a commercial brief)
   - `currency` (varchar 10, default `'EUR'`)
   - `value_proposition` (text, a clear USP to guide the hook)
   - `key_features` (jsonb string[], differentiating features)
   - `target_audience` (varchar 500)
   - `created_at`, `updated_at`

2. **`brand_personas`**: target customer profiles
   - `id` (UUID PK)
   - `company_id` (UUID FK -> `companies.id` ON DELETE CASCADE)
   - `name` (varchar 200, required)
   - `role` (varchar 200, e.g. *"Marketing Director"*)
   - `demographics` (text)
   - `pain_points` (jsonb string[], major problems encountered)
   - `goals` (jsonb string[], priority objectives)
   - `objections` (jsonb string[], typical fears or blockers)
   - `preferred_channels` (jsonb string[], e.g. `["LinkedIn", "YouTube"]`)

3. **`brand_objections`**: frequent objections and verifiable counter-arguments
   - `id` (UUID PK)
   - `company_id` (UUID FK -> `companies.id` ON DELETE CASCADE)
   - `product_id` (UUID nullable FK -> `brand_products.id` ON DELETE SET NULL)
   - `objection` (varchar 500, required)
   - `category` (`pricing` | `product` | `trust` | `technical` | `timing` | `other`)
   - `recommended_response` (text, the recommended answer)
   - `verifiable_proof` (text, a figure, study or benchmark)

4. **`brand_sources`**: official documents and sources of proof
   - `id` (UUID PK)
   - `company_id` (UUID FK -> `companies.id` ON DELETE CASCADE)
   - `title` (varchar 300, required)
   - `kind` (`document` | `faq` | `guideline` | `case_study` | `benchmark` | `proof`)
   - `content` (text, verifiable content holding the figures and facts)
   - `source_url` (varchar 1000)
   - `tags` (jsonb string[])
   - `verified` (`verified` | `draft` | `deprecated`)

## 2. Gap analysis engine and brief preparation

The service `server/src/services/brand-memory.ts` exposes `evaluateAndPrepareBrief(context, input)`, which evaluates any marketing brief submitted (by a user or an autonomous agent) and returns a deterministic diagnosis.

### Analysis rules and detections

| Anomaly code | Severity | Triggering condition | Corrective action |
|---|---|---|---|
| `unspecified_product` | `warning` | No product from the brand memory is specified or mentioned | The agent or user must associate an offer |
| `missing_product_pricing` | `error` | The targeted product has no price or pricing model | Blocking: enter the price before production |
| `missing_value_proposition` | `warning` | The targeted product has no USP defined | Complete the value proposition to anchor the hook |
| `no_personas_defined` | `warning` | No persona is recorded in the client workspace | Define the targets to adapt the vocabulary |
| `unspecified_persona` | `warning` | Personas exist but none is targeted | Select or mention a customer profile |
| `channel_mismatch` | `warning` | The chosen channels are not among the persona's preferences | Adjust the distribution channels |
| `unhandled_objections` | `warning` | Frequent objections are not addressed | Insert the recommended counter-arguments |
| `unverified_claims` | `warning` | Percentages or key figures in the brief do not exist in the verified sources | Validate the figures or add the documentary source |

### Evaluation status

- **`complete`**: all critical information is present, no error, enrichments generated.
- **`action_required`**: non-blocking recommendations or warnings were raised.
- **`incomplete`**: blocking error (e.g. a product without a price).

## 3. API endpoints

All endpoints are mounted under `/api/companies/:companyId/studio/brand`:

- `GET /memory`: fetches the full context (profile, products, personas, objections, sources, statistics).
- `POST /prepare-brief`: analyzes and enriches a marketing brief.
- `POST /products`, `PUT /products/:id`, `DELETE /products/:id`: product CRUD.
- `POST /personas`, `PUT /personas/:id`, `DELETE /personas/:id`: persona CRUD.
- `POST /objections`, `PUT /objections/:id`, `DELETE /objections/:id`: objection CRUD.
- `POST /sources`, `PUT /sources/:id`, `DELETE /sources/:id`: documentary source CRUD.

---

## 4. User interface and Studio integration

The `BrandMemoryPanel` component (`ui/src/components/BrandMemoryPanel.tsx`) is integrated directly into Campaign Studio (`ui/src/pages/CampaignStudio.tsx`). It offers 5 interactive tabs:

1. **Products and pricing**: view offers with price badges and a quick-add form.
2. **Target personas**: persona sheets with roles, pain points and preferred channels.
3. **Objections and answers**: map of objections with arguments and figures.
4. **Sources and proof**: library of verified documents with source URL and tags.
5. **Brief evaluator and gaps**: interactive tool to test any brief and get live alerts about gaps and the enriched brief.
